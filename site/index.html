Previewing a real deploy today means standing up a staging environment, or shipping straight to production and hoping. Cloudflare's own Version Overrides already let you serve an unreleased version on your real domain, for just your own browser — FlarePeek is the one-click front end for it, plus the rest of the toolkit you reach for once a version's actually live.

Everything you check after a deploy, in one place

👁️

One-click version preview

A version staged in your deployment at 0% traffic is invisible to everyone — until you pin it and see it on your actual production domain. Powered by Cloudflare's Version Overrides; no staging setup required.

🎚️

Gradual deployment control

Drag the traffic split between two versions, or roll back, right from the tab you're already on. Both take a deliberate press-and-hold — nothing that moves production traffic happens on a stray click.

🗂️

Several sites at once

Pin the sites you're watching and switch between them in the panel. One more tab follows whatever you're browsing, so a site you've never pinned is still one glance away.

🔗

Bindings at a glance

Every KV namespace, D1 database, R2 bucket, Queue, and more your Worker is bound to — each one links straight to its exact spot in the Cloudflare dashboard.

📊

Error rates, per version

Requests, error rate and CPU p99 for the last 24 hours — plus each version's own error rate, because a 6% failure on a 40% slice reads as 2.6% overall and that is exactly the number that hides a bad rollout.

🚨

Recent errors

The last 30 minutes of errors for the Worker you're looking at, surfaced the moment you open the panel.

🔑

Multi-account auto-detect

Store more than one Cloudflare API token — work, personal, client accounts. FlarePeek figures out which one owns the site you're on, automatically.

How it works

  1. 1

    Create a scoped API token

    FlarePeek gives you a pre-filled link straight to Cloudflare's token page, with exactly the permissions it needs and nothing more.

  2. 2

    Open a site your Worker serves

    FlarePeek recognizes it automatically and shows you what's deployed — the toolbar icon tells you at a glance, before you even click.

  3. 3

    Preview, adjust, or roll back

    Put the new version in your deployment at 0%, preview it yourself, then move the split once it looks right — or roll back. Changes to live traffic take a press-and-hold, so nothing ships by accident.

🔒

No server in the middle, and a switch for the rest

Your API token lives only in local browser storage — never synced, never sent anywhere but Cloudflare's own API. There's no FlarePeek server in between: your browser talks directly to api.cloudflare.com, the same way wrangler does.

To tell you whether a site is yours, FlarePeek has to ask Cloudflare about it — so by default, the address of each site you visit is checked against your account. If you'd rather that didn't happen for everything you browse, switch the panel to manual detection: it then shows the site's name and waits, and asks Cloudflare nothing until you click.
