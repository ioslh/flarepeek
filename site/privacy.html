Privacy

What FlarePeek does with your data

Last updated 26 August 2026

There is no FlarePeek server. Nothing you do in the extension is sent to us, because there is nowhere for it to be sent — no analytics, no telemetry, no crash reporting, no account. Your browser talks directly to Cloudflare's API using your own API token, the same way wrangler does on your machine.

What is stored on your device

All of it lives in your browser's local extension storage, on the machine you are using. None of it is written to Chrome's sync storage, so none of it is uploaded to your Google account or copied to your other devices.

  • Your Cloudflare API tokens, along with whatever label you gave each one and the account email Cloudflare reports for it.
  • The sites you have pinned in the panel, and any Cloudflare account you have locked a particular site to.
  • A small cache mapping a site's address to whichever of your tokens last matched it, so the extension does not have to try each token again next time.
  • Your detection-mode setting — automatic or manual.
  • Any active version override, as a browser request rule for the specific site you applied it to. It is removed when you unpin the version.

Removing the extension removes all of it. You can also delete tokens individually from the extension's settings page at any time.

What is sent, and where

Exactly one destination: api.cloudflare.com. Every request carries your own API token and is made by your browser directly, with nothing in between.

  • The address of the site you are looking at. To tell you whether a site is served by one of your Workers, FlarePeek has to ask Cloudflare about it. In the default automatic mode this happens for each site you visit while the panel is open. If you would rather it did not, switch the panel to manual detection: it then shows the site's name and asks Cloudflare nothing at all until you click.
  • Your Worker's own data — versions, deployments, traffic split, bindings, statistics and recent errors — read from your account when you have a site open.
  • Changes you make, when you deploy a traffic split or roll one back. These are ordinary Cloudflare API writes performed under your token, and take a deliberate press-and-hold to trigger.

What Cloudflare then does with those requests is governed by Cloudflare's own privacy policy, not this one.

Browser permissions

FlarePeek reads the current tab's address so it knows which site to look up, and can add a request header to a site you have chosen — that header is how Cloudflare's Version Overrides feature serves an unreleased version to your browser alone. Permission to touch a given site is requested from you at the moment you first preview a version there, one site at a time, never up front.

The extension does not read, alter or inject anything into the pages you visit. It ships all of its own code; nothing is downloaded and run at runtime.

What never happens

  • No data is sold, shared or transferred to anyone.
  • No advertising, profiling or creditworthiness use.
  • No tracking across sites, and no analytics of any kind inside the extension.
  • Your API token is never logged, never displayed after saving, and never synced.

This website

flarepeek.com is a handful of static files with no scripts from anyone else, no cookies and no analytics. It is hosted on Cloudflare, which keeps ordinary server logs of requests to it, as any web host does.

Changes

If this policy changes in a way that affects what is stored or sent, the date at the top changes with it, and the change will be described in the extension's release notes rather than made quietly.
